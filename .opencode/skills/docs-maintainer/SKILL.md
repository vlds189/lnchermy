# Ведение документации проекта

Каждый значимый модуль исходников `src/` имеет зеркальный MD-файл в `docs/`,
а корневые изменения пишутся в `docs/CHANGELOG.md`. Документация — на русском
(идентификаторы кода — как в исходниках). Это НЕ замена AGENTS.md: AGENTS.md
описывает архитектуру проекта целиком, `docs/` — конкретные файлы и их историю.

## Когда обновлять

1. После существенной правки модуля — обновить его doc-файл в том же заходе
   (ПЕРЕД завершением задачи, а не по отдельной просьбе).
2. По прямой просьбе «обнови документацию» / «задокументируй»:
   - если doc-файлов ещё нет — создать для всех модулей, которые менялись;
   - если есть — прочитать и проверить на устаревание.
3. При создании нового файла/модуля — создать doc-файл.
4. При переименовании/удалении модуля — переименовать/удалить doc-файл.

## Структура папки docs/

Зеркалит дерево исходников (без расширения .rs):

```
docs/
  CHANGELOG.md            # общая история изменений проекта
  main.md                 # src/main.rs
  state.md                # src/state.rs
  ui/
    main_view.md          # src/ui/main_view.rs
    install_view.md
    mod.md
    settings_view.md
  install/
    vanilla.md            # src/install/vanilla.rs
    forge.md
    optifine.md
    java_jdk.md
  ...
```

## Шаблон doc-файла

```markdown
# <Путь к модулю> (<файл.rs>)

## Назначение
2–4 предложения: что делает модуль и зачем он нужен.

## Как работает
- Ключевые структуры/функции с сигнатурами (кратко) и их роль.
- Потоки данных: кто вызывает, кто вызывается (ссылки на другие модули).
- Нестандартные решения и «грабли» — коротко, со ссылкой на AGENTS.md при совпадении.

## История изменений
### YYYY-MM-DD — vX.Y.Z
- <что изменилось и почему, одной строкой на изменение>
```

Секция «История изменений» — обязательная, ведётся по каждому заходу правок.

## Шаблон CHANGELOG.md

```markdown
# Изменения проекта

## vX.Y.Z — YYYY-MM-DD
### Добавлено
- ...
### Исправлено
- ...
### Изменено
- ...
```

## Правила

- **Язык:** русский; тип/имена функций и переменных — как в коде (без перевода).
- **Краткость:** doc-файл — конспект, не копия кода. Не дублируй тело функций.
- **Актуальность:** не пиши «TODO», «в будущем», «в разработке» для уже
  сделанного; не удаляй историю изменений — только добавляй новые записи.
- **Секреты:** в docs/ никогда не попадают токены, пароли, пути с секретами.
- **Согласованность:** если правка меняет архитектуру (новый модуль, смена
  ответственности) — обнови и AGENTS.md (кратко), и соответствующий doc-файл.
- **Не переписывай чужой стиль:** при обновлении существующего doc-файла
  сохраняй его структуру и стиль, только добавляй/правишь нужное.
