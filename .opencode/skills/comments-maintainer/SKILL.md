# Комментарии в коде

Комментарии в этом проекте — на АНГЛИЙСКОМ (идентификаторы в коде тоже).
Комментарий должен объяснять ПОЧЕМУ код такой, а не ЧТО он делает (что читается
из кода само). Добавляй комментарий только если он несёт информацию, которой
нет в коде: «грабли», ограничения, историю решения, неочевидный порядок вызовов.

## Когда писать/обновлять

1. При правке логики — синхронизировать соседние комментарии: если поведение
   изменилось, а комментарий описывает старое — он вредит. Обнови или удали.
2. Когда встречаешь «граблу» (см. раздел ниже) — зафиксировать комментарием.
3. По прямой просьбе «прокомментируй / объясни в коде».
4. НЕ добавляй комментарии «на всякий случай»: шум снижает читаемость.

## Правила

- **FIXME/TODO** — не добавлять без веской причины; если добавляешь, указывай
  конкретную проблему, а не пожелание.
- **Не комментируй очевидное:** `let x = 5; // set x to 5` — бессмысленно.
- **Один комментарий = одна мысль.** Короткие `//`-комментарии в конце строки —
  основной стиль проекта; блоки `//!`/`/* */` — только для назначения модуля
  (в начале файла, как в существующих модулях).
- **Заголовок файла:** у каждого модуля первая строка `// <path> - <одна строка
  о назначении>` (стиль проекта). Синхронизируй при изменении назначения.
- **Язык — английский**, даже если общение с пользователем на русском.
- **Комментарий о «грабле»** снабжай указанием на модуль-первопричину,
  например: `// NOT thread_local — thread-local is invisible to the UI thread`.

## Проектные «грабли», достойные комментария

- egui 0.36: `Panel` вместо `TopBottomPanel`, `CornerRadius` вместо `Rounding`,
  панели принимают `&mut Ui`, `desired_width` — на билдере TextEdit.
- Отключённые виджеты не ховерятся → «кнопка всегда enabled, чтобы ловить
  hover» (Launch/Running).
- `Visuals::interact_cursor` не действует на крестик окна (рисуется через
  `ui.interact`) → ручной `window_close_cursor`.
- Глифы: `✕`, `⟳` отсутствуют в шрифтах egui; работают `✖`, `▶`, `⚠`, `🗑` —
  не менять обратно без проверки cmap.
- Фоновые потоки общаются с UI через глобальные `LazyLock<Mutex<Option<…>>>`,
  никогда `thread_local!`.
- Forge: при `BootstrapLauncher` не класть родительский jar в classpath.
- Скачивание: стрим через `io::copy`, пер-запрос таймаут 20 мин (клиентские
  30 с обрывают 180 МБ JDK).
- Atomic write pattern: temp + rename.

## Процесс

1. Прочитай соседние комментарии и стиль файла.
2. Внеси минимальные точечные правки (Edit), не переписывая фрагменты целиком
   без необходимости.
3. После просьбы «прокомментируй X» — сначала прочитай реализацию X, потом
   комментируй; не комментируй вслепую по названиям.
