# ui/input.rs — инпут с крестиком очистки

## Назначение
`TextInput` — переиспользуемый однострочный инпут с кнопкой-крестиком (✖)
внутри поля, у правого края. Крестик виден при любом непустом тексте (без
требования фокуса); клик очищает строку и возвращает фокус в поле.

## Как работает
- Builder-API зеркалирует `egui::TextEdit::singleline` (набор, нужный
  проекту): `hint_text`, `desired_width`, `id`. Реализует `egui::Widget`,
  поэтому вставляется через `ui.add(TextInput::new(&mut buf)…)`.
- Крестик — не отдельный виджет-кнопка рядом, а оверлей: rect поверх правого
  края поля + `ui.interact(.., Sense::click())`. Поэтому ширина поля не
  меняется при появлении крестика (нет скачков лейаута).
- ВАЖНО (фокус): правило видимости `show_clear_button(buf)` зависит ТОЛЬКО
  от непустоты текста, но не от фокуса. Нажатие на крестик переводит фокус
  с TextEdit на rect крестика (egui фокусирует любой кликнутый виджет) — если
  бы крестик скрывался без фокуса, он исчез бы в момент mouse-down, а release
  на следующем кадре попал бы в пустоту, и клик никогда не завершился бы.
  Эту особенность воспроизводит тест `clear_click_clears_buffer_via_pointer`
  (синтетические RawInput: hover → press → release → буфер очищен, фокус
  вернулся в поле со следующего кадра, т.к. `request_focus` применяется
  кадром позже).
- Возврат — Response самого TextEdit (не крестика): колбэки вызывающих
  (`lost_focus()` и т.п.) продолжают работать как с обычным полем.
- egui 0.36: `TextEdit::show().response` — это `AtomLayoutResponse`
  (Deref на `Response`); настоящий Response — `.response.response`. В тестах
  оффскрин-прогоны идут через `Context::run_ui` + `FullOutput` с явной
  очисткой `textures_delta` (рендерера нет — иначе panic на дропе).
- Глиф ✖ (не ✕ — его нет в шрифтах egui), как и на кнопке Close Game.

## Где применяется
Все однострочные инпуты проекта: username и content-URL (Settings), поиск в
`selector`, поиск версий в launch-пикере (main_view), поле кастомной Java
(install_view), RAM MIN/MAX (Settings). Для RAM учтено, что очистка через ✖
не триггерит `changed()` — пустое значение не сохраняется на диск до
следующего ввода.

## История изменений
### 2026-08-16 — v3.0.8
- Крестик больше не прячется без фокуса поля: `show_clear_button(buf)` без
  аргумента фокуса. Исправляет «крестик есть, но клик ничего не очищает» —
  раньше виджет исчезал на кадре mouse-down (клик фокусирует крестик и уводит
  фокус с поля), release терялся.
- Добавлен тест `clear_click_clears_buffer_via_pointer`: полный pointer-прогон
  press→release через элементы `run_ui`/`Event` API egui 0.36 (кортежный
  `PointerMoved`, `modifiers` у `PointerButton`, очистка `textures_delta`).
### 2026-08-16 — v3.0.7
- Компонент создан; все текстовые поля переведены на него.
