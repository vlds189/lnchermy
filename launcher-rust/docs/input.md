# ui/input.rs — инпут с крестиком очистки

## Назначение
`TextInput` — переиспользуемый однострочный инпут с кнопкой-крестиком (✖)
внутри поля, у правого края. Крестик виден, только если текст непустой и
«семейство» поля держит фокус (сам инпут или сам крестик); клик очищает
строку и возвращает фокус в поле.

## Как работает
- Builder-API зеркалирует `egui::TextEdit::singleline` (набор, нужный
  проекту): `hint_text`, `desired_width`, `id`. Реализует `egui::Widget`,
  поэтому вставляется через `ui.add(TextInput::new(&mut buf)…)`.
- Крестик — не отдельный виджет-кнопка рядом, а оверлей: rect поверх правого
  края поля + `ui.interact(.., Sense::click())`. Поэтому ширина поля не
  меняется при появлении крестика (нет скачков лейаута).
- ВАЖНО (фокус): нажатие на крестик переводит фокус с TextEdit на rect
  крестика (egui фокусирует любой кликнутый виджет). Поэтому правило видимости
  `show_clear_button(buf, any_focus)` учитывает фокус И инпута, И крестика —
  иначе крестик исчез бы в момент mouse-down и клик не завершился бы.
- Фокус крестика проверяется через `ctx.memory(|m| m.has_focus(id))`, т.к.
  Response крестика существует только в кадре, когда он отрисован.
- Возврат — Response самого TextEdit (не крестика): колбэки вызывающих
  (`lost_focus()` и т.п.) продолжают работать как с обычным полем.
- egui 0.36: `TextEdit::show().response` — это `AtomLayoutResponse`
  (Deref на `Response`); настоящий Response — `.response.response`.
- Глиф ✖ (не ✕ — его нет в шрифтах egui), как и на кнопке Close Game.

## Где применяется
Все однострочные инпуты проекта: username и content-URL (Settings), поиск в
`selector`, поиск версий в launch-пикере (main_view), поле кастомной Java
(install_view), RAM MIN/MAX (Settings). Для RAM учтено, что очистка через ✖
не триггерит `changed()` — пустое значение не сохраняется на диск до
следующего ввода.
