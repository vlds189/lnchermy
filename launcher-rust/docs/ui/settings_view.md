# settings_view.rs — экран настроек

## Назначение
Настройки: RAM, ник, Content Index URL, Install (Java / Mods), тема,
обновления.

## Как работает
- View встроен в центральную область главного окна (main_view владеет
  верхним баром, сайдбаром и статус-баром — настроек своих панелей НЕТ;
  `ui/mod.rs` всегда рендерит main_view, а его `CentralPanel` при
  `show_settings` показывает содержимое настроек вместо launch/install).
- Хедер-строка: заголовок + версия (кнопка «‹ Back» удалена — уход из
  настроек только через 🎮-кнопку сайдбара).
- Секции собраны в `ScrollArea::vertical()`.
- Тема: два `radio` (Dark/Light) с SVG-иконками 🌙/☀ слева от радио
  (`icons::tinted`, цвет текста) + `crate::theme::apply()`.
- Обновления: кнопка «Check for updates» (блокирующий вызов
  `update::check_latest()` на UI-потоке) + инлайн-результат `state.update_msg`
  рядом с кнопкой (зелёный = актуальная версия, красный = ошибка/новая есть);
  при наличии новинки — кнопка «Install update & restart».
- Ник и content-URL: редактируются через `TextInput` (ui/input.rs, крестик
  очистки). Текст живёт в постоянном буфере egui data store
  (`username_edit_id()` / `url_edit_id()`), который засевается при каждом
  входе в настройки (флаг `settings_was_open`, сбрасывается при уходе),
  и сохраняется в settings на `lost_focus`. Пустой ник не сохраняется
  (лаунч продолжает использовать последний сохранённый); невалидный ник
  (>3 символов с плохими символами) → `Task::Error`. Уход из настроек
  через 🎮-кнопку сайдбара тоже сбрасывает буферы — `mark_leaving()`.
- RAM MIN/MAX: два `TextInput` напрямую в `settings.ram_min/max`;
  сохраняются только при `changed()` (очистка через ✖ не фурит
  `changed()` — пустое значение не пишется на диск до следующего ввода).
- Install (перенесён из главного вида в v3.0.17): кнопки «Java» и
  «Mods / Resourcepacks» (блокируются при занятом task) открывают модалки
  `install_view` (рендерятся глобально в `main_view::render`, работают из
  любого вида). Vanilla/Forge/OptiFine-установки — по-прежнему в
  launch-picker'е главного вида, сюда они не дублируются.

## История изменений
### 2026-08-18 — v3.0.17
- Блок «Install» перенесён из главного вида в настройки: секция между
  Content Index URL и темой (кнопки «Java» / «Mods / Resourcepacks»,
  `install_section()`, дренаж-манифеста остался в launch-секции главного
  вида — picker'у нужен каталог).

### 2026-08-17 — v3.0.14
- Кнопка «‹ Back» в хедере удалена: уход из настроек — только через
  🎮-кнопку сайдбара (они же сбрасывают буферы `mark_leaving()`).

### 2026-08-17 — v3.0.13
- Радио темы: глифы 🌙/☀ в подписи заменены на SVG-иконки (moon.svg /
  sun.svg из `ui/icons.rs`) слева от радио-кнопок.
### 2026-08-17 — v3.0.12
- Настройки больше не отдельная вкладка: содержимое рендерится в
  центральной области main_view (chrome окна остаётся: верхний бар,
  сайдбар с ⚙, статус-бар, progress overlay). Собственные `Panel::top` +
  `CentralPanel` удалены; хедер «‹ Back» стал строкой над ScrollArea;
  `ui/mod.rs` безусловно рендерит main_view.
### 2026-08-17 — v3.0.10
- RAM-пресеты удалены: остались только поля ввода MIN/MAX (раньше
  секция «Presets» с 5 кнопками + «Custom»-поля).
### 2026-08-16 — v3.0.8
- Поле ника: убран откат сохранённого ника в буфер при пустом поле — после
  очистки через ✖ поле остаётся пустым (раньше `lost_focus` на кадр клика
  по крестику возвращал старый ник, и очистка «не работала»); пустое поле
  просто не сохраняется.
### 2026-08-12 — v2.0.0 (до v3.0.0)
- Результат проверки обновлений выводится инлайн рядом с кнопкой
  («You are on the latest version (v…)»), поле `update_msg` в AppState.
